# Anatomy of a Chunk

A Chunk is the atomic unit of identity in the Athanor Protocol. Each chunk is a self-contained piece of knowledge about a person, enriched with metadata that makes it useful for both retrieval and reasoning.

## Structure

```json
{
  "chunk_id": "TDM-HEUR-001",
  "author": "observer@example.com",
  "cluster": "technical-decision-making",
  "type": "heuristic",
  "uniqueness": "CRITICAL",
  "source": "interview",
  "confidence": 0.92,
  "context_tags": ["architecture", "microservices", "team-size"],
  "linked_chunks": ["TDM-ANTI-003", "PV-BELI-012"],
  "content": "Always start with a monolith unless you have 50+ engineers. The coordination cost of microservices is invisible until it's crushing you — and by then you've built organizational boundaries around service boundaries that are nearly impossible to undo."
}
```

## Fields

### chunk_id

Format: `CLUSTER-TYPE-NNN` (e.g., `TDM-HEUR-001`).

- **Cluster prefix**: 2–4 uppercase letters derived from the cluster name
- **Type code**: 3–5 uppercase letters (HEUR, ANTI, PREF, BELI, FACT, SKIL, EMOT, STOR, CONT, STYL, FRAM, RANT, META, RITU)
- **Sequence number**: Zero-padded 3-digit number

IDs are auto-generated by the Portrait class.

### type

One of 14 chunk types. See [Three Layers](three-layers) for the full taxonomy.

### uniqueness

How distinctive this chunk is to the person:

- **CRITICAL** — Defines them. Remove this and the clone is fundamentally wrong.
- **HIGH** — Distinctive but not singular. Important for accuracy.
- **MEDIUM** — Contributes to fidelity but could be shared by many people.

The protocol requires at least 30% of chunks to be CRITICAL to ensure portraits aren't diluted with generic knowledge.

### confidence

A float from 0.0 to 1.0 indicating how certain we are about this chunk:

| Range | Meaning |
|---|---|
| 0.9–1.0 | Direct, unambiguous evidence |
| 0.7–0.89 | Strong evidence with minor inference |
| 0.5–0.69 | Moderate evidence, some ambiguity |
| 0.3–0.49 | Weak evidence, limited data |
| < 0.3 | Speculative — flagged for review |

Clones modulate their certainty based on chunk confidence. A chunk at 0.4 might be expressed as "I think I tend to..." while 0.95 becomes "I absolutely..."

### source

Where the chunk was observed. One of: `interview`, `email`, `document`, `code`, `meeting`, `chat`, `social`, `observation`, `inferred`.

### cluster

A semantic grouping (e.g., `technical-decision-making`, `team-leadership`, `emotional-landscape`). Recommended clusters are defined in the protocol, but custom clusters are allowed.

### content

The chunk text itself. Minimum 20 characters. Should be self-contained — readable without context from other chunks.

### context_tags

Free-form tags for additional categorization and searchability.

### linked_chunks

Explicit references to related chunk IDs. These are separate from the formal Relation system — think of them as informal "see also" links.

## Validation Rules

The validator enforces:

- Content minimum length (20 characters)
- Confidence within [0.0, 1.0]
- Valid chunk_id format
- Known type and uniqueness values
- At portrait level: ≥30% CRITICAL chunks, no orphaned chunks, cluster coverage
